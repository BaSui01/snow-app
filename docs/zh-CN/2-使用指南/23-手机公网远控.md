# 部署手机公网远控

> 适用于 Windows、macOS 与 Linux 桌面版 Snow。部署过程由 Snow 内置程序完成，不调用聊天 AI，也不要求用户理解 Caddy、PEM 或 TLS 名称。公网入口只使用 SSH2 反向隧道。

## 目标

部署完成后，手机关闭 Wi-Fi 仍可通过 `https://snow.<你的域名>` 打开 Snow，并扫描设置页中的公网二维码完成配对。

## 需要提前准备什么

1. 一台长期运行的 Linux 公网服务器，厂商不限：Ubuntu 22+、Debian 11+、Fedora 44+、CentOS Stream/RHEL/Rocky/AlmaLinux 9+；仅 x86_64/amd64、独立公网 IPv4，推荐至少 1 核 1 GB。不要使用抢占式或竞价实例。
2. 一个自己持有的域名，注册商和后缀不限。不需要另外购买 SSL 证书、CDN、建站或企业邮箱服务。
3. 服务器的 SSH 登录方式：`root` 密码，或私钥；普通用户也可以，但必须有免密码 `sudo` 权限。

如果手机与电脑始终在同一 Wi-Fi，只需扫描局域网二维码，不需要服务器或域名。

## 隧道方式是 SSH2

Snow 在“设置 → 手机远控 → 第一次配置”使用进程内 SSH2 反向隧道：不启动外置隧道子进程，只需 `snow` 一条 A 记录，SSH2 隧道端口默认 `7001`（需在安全组放行），回环端口默认 `18080`。

- 桌面端主动发起出站 SSH 连接；服务器端由独立的受限 `snow-tunnel-sshd` 提供，绝不修改系统自带 sshd。
- 隧道专用私钥保存在本机系统安全存储中，不随配置包导出；导入不含私钥的配置包后，需要用“自动部署并连接”重新授权此设备。
- 完整说明（DNS 记录、安全组端口、排错命令与手动安装脚本）见 [自建公网远控模板](../../../deploy/remote-control/README.md)。

## 只需手工完成两件事

Snow 无法通用地修改所有云厂商的控制台，因此请先完成：

1. 在域名 DNS 控制台添加一条 A 记录，记录值填写服务器公网 IPv4：
   - 主机记录 `snow`
2. 在服务器安全组或云防火墙中允许入站 TCP `22`、`80`、`443`、`7001`（默认 SSH2 隧道端口，可在部署表单中修改）。不要开放 `18080`（默认回环端口，可在部署表单中修改）。

DNS 生效可能需要几分钟。Snow 设置页的“检测 DNS”会直接告诉你记录是否正确。

## 让 Snow 自动部署

1. 打开“设置 → 手机远控 → 自建服务器公网连接”。
2. 填写服务器公网 IPv4、根域名（例如 `example.com`）、SSH 用户名和端口，以及 SSH2 隧道端口（默认 `7001`）与回环端口（默认 `18080`）。
3. 选择密码或私钥登录。密码和私钥口令只在本次部署期间保存在内存中，不写入远控配置。
4. 点击“检测 DNS”。记录正确后，点击“自动部署并连接”。
5. 等待 Snow 检查系统、上传内置安装程序、安装受限 sshd 与 Caddy、生成专用密钥、导入配置并验证公网 HTTPS。

Snow 直接从安装包的固定资源目录读取部署脚本，不会让聊天 AI 搜索磁盘。服务器生成的隧道元数据在内存中导入，不会在本机留下明文配置包；导入后服务器上的临时元数据也会删除。

## 验证

部署成功时，页面会显示“本机 WAN”“SSH2 隧道”“HTTPS 探测”均正常，并生成公网二维码。关闭手机 Wi-Fi，使用蜂窝网络扫描二维码，测试查看会话、发送消息、停止任务和上传附件。

服务器只应公开 `22`、`80`、`443` 与 SSH2 隧道端口（默认 `7001`）；回环隧道端口（默认 `18080`）必须只监听 `127.0.0.1`。Snow 会在部署末尾检查这一点。

## 常见问题与恢复

- “DNS 尚未生效”：核对 `snow` A 记录是否指向页面中填写的公网 IPv4，等待几分钟后重试。
- 使用代理后始终显示错误的 `198.18.x.x`：这是部分 VPN/TUN 的 fake-IP。Snow 会自动通过 HTTPS 公共 DNS 复核，无需关闭代理或修改正确的 A 记录。
- “服务器系统不支持”：使用 Ubuntu 22+、Debian 11+、Fedora 44+、CentOS Stream/RHEL/Rocky/AlmaLinux 9+，仅 x86_64/amd64。
- SSH 连接失败：核对公网 IP、端口、用户名以及密码或私钥；不要把密码或私钥内容发到聊天中。
- 安装完成但公网不可达：核对安全组是否允许 TCP `80`、`443` 与 SSH2 隧道端口（默认 `7001`），并确认服务器没有额外防火墙阻止它们。
- 部署中断：可直接重新点击部署。Snow 会清理临时脚本；未完整验证的配置不会保持自动连接。
- 重新部署同一台服务器：复用受限 sshd、Caddy 与服务器主机密钥，重新部署会生成本机新密钥并替换服务器上已授权的公钥。只有端口或版本变化时才重写配置并重启对应服务。
- 更换根域名后重新部署：按新域名重写 Caddy 配置并申请新证书，受限 sshd、服务器主机密钥与已授权的公钥都不受影响。
- 手机遗失或链接泄露：在“公网令牌”中重新生成并确定更换；怀疑隧道密钥泄露时重新部署以替换服务器上授权的公钥。
