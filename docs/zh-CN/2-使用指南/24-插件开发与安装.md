# 24-插件开发与安装（Plugins）

> 适用：Snow App 桌面端（Windows / macOS / Linux）。插件是**本地目录形式**的扩展包，为右侧面板提供自定义标签页；本文同时覆盖「安装与卸载（本地目录与插件市场）」「自己写一个插件」与「发布到插件市场」。

## 目标

- 从本地目录或**插件市场**安装插件，并在右侧面板打开它提供的面板；
- 会写 `plugin.json` 清单与入口模块，能读取元数据、通过 `api.write` 写入应用数据、保存插件私有设置并声明隐私域；
- 把插件**发布到插件市场**：准备 Release 资产、计算 SHA-256、提交索引条目；
- 让 AI 通过 `config` 工具的 `plugins` 域**自动完成安装、启停、重载与卸载**，不必打开设置界面。

## 前置条件

- 插件目录必须包含 `plugin.json` 与清单里声明的入口文件（`entry`，默认 `index.js`），入口文件缺失会直接安装失败。
- 插件以**本地代码**运行：`renderMode: "esm"` 的入口在主窗口渲染进程里作为 ES 模块执行，拥有与页面相同的 DOM 与网络能力；`renderMode: "iframe"` 的入口在独立沙箱文档中运行，只能通过桥访问受限 API。请只安装可信来源的插件。
- 插件对应用数据是「只读 + 受控写入」：读取走 `api.metadata`，写入走 `api.write`，写动作按其 `scope` 决定是否需要在 `privacy` 中声明（见「可写能力」一节）。
- 安装时目录总大小上限 **128 MB**，并会跳过 `.git` 与 `node_modules`。
- 单个文本文件读取上限 8 MB，单个二进制资源上限 16 MB。
- 「插件市场」需要能访问 GitHub raw 或 jsDelivr 镜像；发布插件需要插件自己的 GitHub 仓库与 Release。

## 入口

侧边栏底部的 **插件** 按钮（带已安装数量角标）打开插件管理页面——它是主内容区的一个视图（视图 id `plugins`），不是设置页，也没有独立设置页 id。页面顶部有三个顶层标签页：**插件列表**（角标为面板插件 + 客户端脚本总数）、**插件市场** 与 **元数据清单**（角标为元数据域总数）：

| 标签页         | 内容                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **插件列表**   | 插件管理主区域；内部还有 **面板插件** / **脚本插件** 两个次级小标签（各带数量角标），前者是本文其余章节介绍的本目录插件，后者是客户端 UI 脚本 |
| **插件市场**   | 从 snow-plugin-store 索引一键安装或更新面板插件与用户脚本；安装、更新与作者发布流程见「插件市场」一节                                         |
| **元数据清单** | 插件可读的应用元数据域、可写动作与网络能力清单                                                                                                |

「面板插件」小标签下的工具栏提供 **从目录安装** 与 **刷新** 两个动作；每行显示插件的版本、作者与渲染模式，声明了隐私数据域的插件会用琥珀色标签逐个列出所申请的数据（文案跟随界面语言，如「API 密钥」「会话消息」），并在下方展示清单里的 `note` 说明；点击任意琥珀色标签即可打开「隐私域声明」弹窗，逐个域给出用途说明，以及它放行的可读元数据域（字段级声明会标出具体字段）与可写能力（按写域聚合的动作数），并标出声明位置（`plugin.json` 的 `privacy` / 脚本头的 `@snow-privacy`）。「脚本插件」小标签下同一位置也用同样的琥珀色标签列出脚本的 `@snow-privacy` 声明，点击弹出同一个弹窗。**元数据清单** 标签页以「可读元数据 / 可写能力 / 网络能力」三个子标签并列展示：按分组列出全部 34 个域及一句话说明、隐私声明要求、实时/轮询与可用参数，支持关键词搜索；可写能力按动作给出所需 `scope` 与声明状态；网络能力列出 `api.net.fetch` 外部请求能力（经主进程转发，无需隐私声明）。每个插件行上的「可读元数据 n/34」与「可写能力 n/206」入口用同一份清单标出该插件已声明（可读/可写）与未声明（调用会被拒绝）的域与动作，方便用户核对 `privacy` 声明。该页面只做管理，打开面板请用顶栏加号菜单的「插件」分组或右侧面板的插件入口。

## 脚本插件（客户端 UI 脚本）

「插件列表 → 脚本插件」小标签管理的是**注入 Snow 桌面窗口本身**的客户端 UI 脚本，和同一层的「面板插件」是两类不同形态的扩展——共用同一个管理页面，但存储、运行方式与能力边界完全独立：

| 维度     | 面板插件（插件列表 → 面板插件）                                                                 | 客户端 UI 脚本（插件列表 → 脚本插件）                                                                                                                             |
| -------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 形态     | 本地目录包：`plugin.json` + 入口文件（`entry`）                                                 | 单文件 Tampermonkey 兼容脚本（`// ==UserScript==` 元数据头）                                                                                                      |
| 运行方式 | `renderMode: "esm"` 的主窗口渲染进程 ES 模块；`renderMode: "iframe"` 的沙箱文档                 | 默认运行在**独立隔离世界**（沙箱档，拿不到 `window.snow`）；声明 `@snow-sandbox false` 或 `@grant unsafeWindow` 后改在主世界执行（完全权限档）                    |
| 能做什么 | 提供右侧面板标签页，通过 `api.metadata` / `api.write` 读写应用数据（受 `privacy` 声明约束）     | 用锚点 / 插槽契约定制界面，调用 `GM_*` 与 `snow` API（受作用域与沙箱档约束）；同样通过 `snow.metadata` / `snow.write` 读写应用数据（受 `@snow-privacy` 声明约束） |
| 界面入口 | 加号菜单「插件」分组、右侧面板标签体系                                                          | 无独立面板，直接作用于界面元素                                                                                                                                    |
| 存储位置 | `~/.snowapp/plugins/<pluginId>/` + `app_plugins` 表                                             | `~/.snowapp/browser-script/{script_id}.user.js` + `userscripts` 表（`target` 为 `client` / `all`）                                                                |
| 安装方式 | **从目录安装**、`config` 工具的 `plugins` 域                                                    | **新建脚本** / **导入文件** / **从链接安装**（https 直链）/ **让 AI 制作**、`config` 工具的 `userscripts` 域                                                      |
| 图标     | `plugin.json` 的 `icon`（`lucide:Name`、插件目录内相对路径；面板可按 `panels[].icon` 单独覆盖） | 元数据头的 `@icon` / `@iconURL`（`lucide:Name`、http(s) URL 或 data URI），显示在脚本插件列表                                                                     |

该小标签内可**新建**（弹窗编辑器预填客户端脚本模板）、**导入文件**、**从链接安装**，列表为空时还会在空状态里给出 **让 AI 制作** 需求框（描述需求后关闭插件页面并新建会话自动发送；AI 先加载 `snow-app-docs` 技能定位内置文档，再按 22 号文档的客户端脚本规范写出 `.user.js` 并安装启用），并对每个脚本启用 / 停用 / 编辑 / 删除；市场索引中存在更高版本时行内直接出现 **更新** 按钮（原地更新并保持启用状态，与「面板插件」一致）。新建与编辑都用与「设置 → 浏览器设置 → 油猴脚本」同一个大号弹窗编辑器（`Modal` + 带行号与高亮的 `FileViewerContent`，编辑时虚拟文件名为 `<脚本名>.user.js`；保存即写库、重新匹配并立即生效，关闭弹窗即取消），连续出错 5 次的脚本会被自动禁用。指令表（含 `@snow-privacy`）、GM / `snow` / `snow.metadata` / `snow.write` API 清单、锚点与插槽契约、最小示例见 [22-油猴脚本](22-油猴脚本.md) 的「客户端脚本（桌面窗口）」。

> 两个入口共用同一张 `userscripts` 表：脚本插件小标签只显示 `target` 为 `client` / `all` 的脚本，浏览器设置里的「油猴脚本」列表只显示 `browser` 与 `all`；按元数据头里的 `@snow-target` 或 `@match snow://client/<view>` 决定归属。

## 操作步骤

### 1. 安装插件

1. 点击 **从目录安装**，在系统目录选择框里选中插件目录（包含 `plugin.json` 的那一层）。
2. 后端读取并校验清单，把目录复制到 `~/.snowapp/plugins/<pluginId>/`（Windows 为 `C:\Users\<用户名>\.snowapp\plugins\<pluginId>\`），写入应用数据库并**默认启用**。
3. 同名插件（`id` 相同）重复安装是**原地替换**：目录被新内容覆盖，已保存的启用状态保留。

```mermaid
flowchart TD
    A[选择插件目录] --> B{存在 plugin.json}
    B -- 否 --> C[报错: Missing plugin.json]
    B -- 是 --> D[解析 id/entry/renderMode 等字段]
    D --> E{id 合法且入口文件存在}
    E -- 否 --> F[报错: id 非法或入口文件缺失]
    E -- 是 --> G[复制目录到 ~/.snowapp/plugins/id]
    G --> H[写入 app_plugins 记录并启用]
    H --> I[面板出现在右侧面板与加号菜单]
```

### 2. 管理已安装插件

列表每行显示名称、版本、作者、渲染模式与安装路径，并提供：

- **启用开关**：立即生效；禁用后其面板不再出现在加号菜单，已打开的面板会提示「插件已禁用」。
- **重新读取清单**：手工修改过安装目录里的 `plugin.json` 后用它重新解析（清单 `id` 与记录不一致会报错）。
- **在文件夹中显示**：定位到 `installPath`。
- **更新**：与「插件市场」共用同一份索引——索引中存在更高版本时行内直接出现 **更新** 按钮（悬停显示 `已安装 v<旧版本> → v<新版本>`），点击即原地更新，无需切换到市场标签页；条目要求的 `minAppVersion` 高于当前应用版本时按钮禁用并在悬停提示中说明原因。
- **卸载**：二次确认后删除数据库记录并**删除插件目录**（不可恢复）。

### 3. 打开插件面板

插件在 `panels` 里声明的每个面板都会出现在顶栏 **加号菜单** 的「插件」分组与右侧面板标签体系中；点击即以右侧面板标签打开，多个面板可同时打开。面板标题按当前界面语言从 `panels[].title` 解析。

### 4. 编写一个插件

最小目录结构：

```text
my-plugin/
  plugin.json
  index.js
  locales/
    zh-CN.json
  style.css
```

`plugin.json` 示例：

```json
{
  "id": "com.example.hello",
  "name": { "default": "Hello", "zh-CN": "你好" },
  "description": { "default": "Demo panel", "zh-CN": "示例面板" },
  "version": "1.0.0",
  "author": "You",
  "license": "MIT",
  "icon": "lucide:Sparkles",
  "renderMode": "esm",
  "entry": "index.js",
  "panels": [
    {
      "id": "main",
      "title": { "default": "Hello", "zh-CN": "你好" },
      "icon": "lucide:Sparkles"
    }
  ],
  "locales": { "zh-CN": "locales/zh-CN.json" },
  "styles": ["style.css"],
  "privacy": {
    "scopes": ["apiKeys"],
    "note": "只读取 API 档案用于展示模型列表。"
  }
}
```

字段说明（均为解析后的实际语义）：

| 字段                              | 类型               | 必填 | 默认值         | 约束与说明                                                                                                                       |
| --------------------------------- | ------------------ | ---- | -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `id`                              | 字符串             | 是   | —              | 仅字母、数字、`.`、`-`、`_`，最长 96 字符，不能以 `.` 开头；同时是安装目录名与数据库主键                                         |
| `name`                            | 字符串或本地化对象 | 否   | `id`           | 对象键支持 `default`、`zh-CN`、`zh-TW`、`en`，其余键原样保留                                                                     |
| `description`                     | 字符串或本地化对象 | 否   | `name.default` | 同上                                                                                                                             |
| `version`                         | 字符串             | 否   | `1.0.0`        | 仅展示                                                                                                                           |
| `author` / `homepage` / `license` | 字符串             | 否   | 空             | 仅展示                                                                                                                           |
| `icon`                            | 字符串             | 否   | 空             | `lucide:IconName` 用内置图标；其它值按插件目录内**相对路径**读取为图片；`http(s):` 与 `data:` 前缀不作为资源解析                 |
| `renderMode`                      | `esm` 或 `iframe`  | 否   | `esm`          | 大小写不敏感，非法值回退 `esm`                                                                                                   |
| `entry`                           | 字符串             | 否   | `index.js`     | 相对插件目录的路径，**必须存在**，否则安装失败                                                                                   |
| `panels`                          | 数组               | 否   | `[]`           | 每项 `id` 必填；`title`（也接受 `name`）缺省为 `id`；`entry` 缺省沿用顶层 `entry`；`icon` 缺省沿用插件图标；`widthHint` 原样透传 |
| `locales`                         | 对象               | 否   | `{}`           | 语言标签到语言包文件相对路径的映射                                                                                               |
| `styles`                          | 字符串数组         | 否   | `[]`           | CSS 文件相对路径，面板挂载时注入、卸载时移除                                                                                     |
| `privacy`                         | 数组或对象         | 否   | `[]`           | 数组形式为敏感域列表；对象形式取 `scopes`（也接受 `domains`）与 `note`；也接受 `permissions` 作为键名                            |
| `privacyNote`                     | 字符串             | 否   | 空             | 只有 `privacy` 用对象形式时的 `note` 会被读取并展示                                                                              |
| `minAppVersion`                   | 字符串             | 否   | 空             | 当前仅记录与展示，**不做版本拦截**                                                                                               |

清单面板可额外声明 `"chatInput": true`（仅布尔 `true` 生效，缺省 `false`），开启输入工具栏入口；不影响既有 `entry`、`icon`、`widthHint` 和隐私规则，详见 6.1。

### 5. 写入口模块（`renderMode: "esm"`）

入口会被当作 ES 模块动态导入，可任选一种导出方式：

```javascript
// 方式一：默认导出 React 组件（注入 props: api / locale / panelId / panel / pluginId / isActive / inputText）
// inputText 为输入框当前原始内容（保留 @@file:...@@ 等标签标记），随输入实时更新
export default function Panel({ api, isActive }) {
  const { React } = window.SnowAppPlugin;
  const [count, setCount] = React.useState(0);
  return React.createElement(
    "button",
    { onClick: () => setCount(count + 1) },
    api.t("clicked", {
      defaultValue: "已点击 {{count}} 次",
      values: { count },
    }),
  );
}

// 方式二：导出 mount(container, api)，返回清理函数或 { unmount }
export function mount(container, api) {
  container.textContent = api.name;
  return () => {
    container.replaceChildren();
  };
}
```

挂载前宿主会注入全局对象 `window.SnowAppPlugin`：

| 成员                      | 说明                                                   |
| ------------------------- | ------------------------------------------------------ |
| `React` / `createElement` | 宿主 React 实例，避免插件自带副本                      |
| `icons`                   | lucide 图标命名空间（也可用 `api.ui.icon(name)`）      |
| `api`                     | 与 `mount(container, api)` 收到的同一个运行时 API 对象 |
| `locale`                  | 当前界面语言（`en` / `zh-CN` / `zh-TW`）               |
| `plugin`                  | `{ id, version, installPath }`                         |

`renderMode: "iframe"` 时不注入上述全局对象，入口在沙箱文档中通过 `window.SnowPlugin` 访问桥接 API，字段为 `runtime: "iframe"`、`plugin: {id, name, version}`、`locale`、`t`、`metadata`、`write`、`storage`、`assets`、`net`、`on`、`log`，语义与下表一致（iframe 可以请求 `metadata`、`write`、`storage`、`assets`、`net` 五类能力，其中写入只有 `api.write.run` 与 `api.write.domains`，没有按域展开的语法糖）。

### 6. 运行时 API

| API                                                                      | 说明                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api.id` / `api.version` / `api.name` / `api.installPath` / `api.locale` | 插件标识与当前语言                                                                                                                                                                                                            |
| `api.t(key, { defaultValue, values })`                                   | 语言包取词，`key` 缺失时回退 `defaultValue` 或键名；`{{name}}` 按 `values` 插值                                                                                                                                               |
| `api.metadata.get(domain \| domain[], { params })`                       | 采集元数据域，返回 `{ generatedAt, domains, denied, withheld, unknown }`                                                                                                                                                      |
| `api.metadata.subscribe(domain, listener, { params, intervalMs })`       | 订阅：`live` 域随运行时快照变化（200 ms 防抖）推送，其余域按 `intervalMs`（最小 1000 ms）轮询；不传间隔只推一次初值；返回 `Promise<{ unsubscribe }>`，需 `await`                                                              |
| `api.metadata.domains()`                                                 | 列出域清单与授权状态：`{ id, scope, granted, live, sensitiveFields }`                                                                                                                                                         |
| `api.write.<domain>.<action>(params)`                                    | 调用一个写动作（仅 ESM），等价于 `api.write.run("<domain>.<action>", params)`                                                                                                                                                 |
| `api.write.run(actionId, params)`                                        | 按动作 id 调用写动作，返回 `{ ok, action, data, denied, error }`（见「可写能力」）                                                                                                                                            |
| `api.write.domains()`                                                    | 列出写动作与声明状态：`{ id, granted, actions: [{ id, scope, granted, summary }] }`                                                                                                                                           |
| `api.net.fetch(url, { method, headers, body, timeoutMs })`               | 经主进程网络栈发起外部 HTTP 请求：走应用代理设置、无 CORS 限制、不携带 Cookie；返回 `{ ok, status, statusText, headers, body, url, error }`，网络层失败不抛异常而是以 `error` 返回。超时默认 30s（上限 120s），响应体上限 5MB |
| `api.storage.get / set / remove / all`                                   | 插件私有持久化（应用数据库 `app_plugin_values` 表），值为字符串                                                                                                                                                               |
| `api.storage.getJson / setJson`                                          | 上述接口的 JSON 便捷封装                                                                                                                                                                                                      |
| `api.assets.resolve(relativePath)`                                       | 按相对路径读取插件目录内的图片等资源，返回 data URL；失败返回 `null`                                                                                                                                                          |
| `api.ui.React` / `api.ui.icon(name)`                                     | 与 `window.SnowAppPlugin.React` / 图标查找等价                                                                                                                                                                                |
| `api.log(...args)`                                                       | 带 `[plugin:<id>]` 前缀的日志                                                                                                                                                                                                 |

`params` 常用键：`projectId`、`projectPath`、`directoryId`、`conversationId`（缺省取当前激活项目/会话），以及各域自己的分页与过滤参数。

`runtime` 域是实时数据源：`conversation` 是焦点会话的完整快照，含 `conversationId`、`sessionKey`、`title`、`directoryId`、`isStreaming`、`isPaused`、`isAborting`、`streamTokenCount`、`streamElapsedMs`、`streamTtftMs`、`streamStartedAt`、`runTtftMs`、`lastRunDurationMs`、`streamingConversationIds` 等；`streamingSessions` 列出所有正在运行的会话（含新会话槽位），每项含 `sessionKey`、`conversationId`、`title`、`directoryId`、`isStreaming`、`isPaused`、`isAborting`、`messageCount`、`tokenCount`、`elapsedMs`、`ttftMs`、`runTtftMs`、`startedAt`、`lastRunDurationMs`、`runTokenUsage`。`startedAt` 是本轮 run 的墙钟起点，实时墙钟时长按 `Date.now() - startedAt` 计算，实时速度按 `tokenCount / elapsedMs` 计算，与输入框上方的流式指标条同源。`chatInput` 是输入区的实时数据（由输入区在挂载期间发布，输入区未挂载时保留最后一次发布值）：`inputText` 是输入框当前原始内容（保留 `@@file:...@@`、`@@image:...@@` 等标签标记，空串表示未输入，随输入实时变化），`conversationId` 是输入区当前绑定的会话（null = 新会话输入区），`maxContextTokens` 是会话生效 API 档案的上下文窗口上限，`isLoadingApiConfig` 是 API 配置加载态。配合 `conversation.tokenUsage`（Rust 已归一化，cache read 是 input 的子集）即可复刻输入框右侧的 Token 用量环：`total = inputTokens + outputTokens`，占比按 `min(total / maxContextTokens, 1)` 计算（`maxContextTokens` 为空时退回以 total 为分母的满环口径），`isLoadingApiConfig` 为 `true` 时按占位环处理，避免把加载中的配置误判为满容量。

### 6.1 提示词优化与安全草稿（ESM）

面板声明 `panels[].chatInput: true`（布尔值，缺省 `false`）后，该已启用面板的小图标出现在输入工具栏 `toolbar-right` 的模型选择器左侧，图标沿用面板 / 插件图标。`chatInputTitle` 是入口专用本地化标题，缺省回退 `panel.title`，可以让魔杖 tooltip 显示「优化草稿」、右侧配置面板显示「优化策略」。`chatInputAction` 是入口模块的合法 JS 导出名（支持 Unicode IdentifierName，非法 / 空值归一化为空）：**空值仍只打开面板**；ESM 非空值则只在用户点击魔杖时调用该导出，不打开右侧面板。旁边独立小齿轮打开配置面板，即使纯文本为空 / 没有 API 也可配置。iframe 不执行 Action，保留只打开面板的行为。纯文本为空（只有 chip 也算空）、没有有效 API 配置、配置加载中、流式生成 / 停止中 / 压缩中时禁用执行入口。加号菜单与右侧面板入口保持原有行为，不绑定特定插件 id。

`optimizationInstructions?: string` 是可选优化 meta prompt / 策略，按 **Unicode 码点**计数，原值最多 8000 字符（不是 UTF-16 长度），超限 / 非字符串在 renderer 与 backend 均拒绝。backend 去除首尾空白后，空值等同省略，旧请求行为不变；策略使用独立可信 system 段落，不能覆盖固定安全底线。不要把 API 密钥或附件内容拼到策略里。

#### 通用输入 Action 签名与交互

清单示例：

```json
{
  "id": "settings",
  "title": { "default": "Optimization strategy", "zh-CN": "优化策略" },
  "chatInput": true,
  "chatInputAction": "optimizeDraft",
  "chatInputTitle": { "default": "Optimize draft", "zh-CN": "优化草稿" },
  "icon": "lucide:WandSparkles"
}
```

入口模块导出 `async optimizeDraft({ api, signal, onStatus, confirm }): Promise<PluginChatInputActionResult>`；不调用 `mount`，配置面板仍是独立入口。宿主导出类型如下（类型路径 `src/renderer/plugins/pluginApi.ts`）：

```typescript
type PluginChatInputActionContext = {
  api: PluginRuntimeApi;
  signal: AbortSignal;
  onStatus: (message: string) => void;
  confirm: (message: string) => Promise<boolean>;
};
type PluginChatInputActionResult = {
  message?: string;
  preview?: string;
  apply?: () => Promise<PluginChatInputActionResult>;
  undo?: () => Promise<void>;
};
```

- 右侧面板只配置优化 meta prompt / 策略并保存私有偏好；默认魔杖一次点击执行优化，插件调用安全 `applyDraft` 成功后自动回填并返回基于 `restoreToken` 的 `undo` 闭包，宿主显示显眼「还原」。无需再次到右侧面板操作，不会发送消息。
- 可选预览确认模式返回 `preview + apply`，宿主在输入区小预览框显示纯文本结果、复制、应用。`apply` 成功再返回含 `undo` 的结果。草稿已失效时返回 `preview` 而不返回 `apply`，仅可复制；不能重新捕获新草稿强行应用旧结果。
- `onStatus` 更新输入区状态；执行 / 应用 / 还原期间显示转圈，再次点击主按钮只取消本次 Action 信号，绝不停止普通聊天。Action 应把 `signal` 传给 `api.ai.optimizePrompt`；宿主绑定 API 还会合并该 Action 的取消信号。
- `confirm` 使用宿主现有 Modal：确认返回 `true`，关闭 / ESC 拒绝，运行被取消或上下文失效会结清等待并中断 continuation。它只是运行时用户 UI 确认，不是工具授权，也不是收费请求的自动批准。
- 每次点击重新 `loadPluginMessages`、创建 **fresh API**（重新读取当前插件 storage 偏好；读取失败不启动 Action）、`loadPluginModule` 后取 `module[panel.chatInputAction]`。不缓存配置面板的 API/storage 快照；`api.storage` 接口未改。加载各 await 阶段检查取消；缺少导出显示错误，不调用收费 fallback。
- 参数 / API 档案 / 模型、项目 / 真实或 pending 会话切换、插件更新 / 禁用 / 卸载、输入区卸载、进入流式 / 停止 / 压缩时自动取消并使旧回调失效。晚到的状态、确认、结果和 Action 绑定 API 的 AI/写调用被拦截；已完成结果移除 `apply/undo` 后可保留只读预览。打开配置齿轮也会取消当前 Action，避免配置中旧策略结果继续回填。
- 配置面板挂载、模块 import 顶层、metadata 订阅 / 刷新均不得调用 Action 或付费 API。宿主只在用户点击时调用导出；ESM 是可信本地代码，并不是对恶意插件顶层代码的沙箱。自动回填 / 还原仍必须走 token 动作，不能猜写 DOM、绕过 privacy 或普通会话发送通道。

`api.ai.optimizePrompt(options): Promise<{ content: string }>` **仅限 ESM**；iframe 桥没有 `ai` 能力。`options` 为：

| 字段                       | 类型                    | 契约                                                                                       |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------------------ |
| `draft`                    | string                  | 必填非空纯文本；只能在用户明确点击优化后发送，不得挂载、订阅或打开面板即请求               |
| `conversationId`           | string?                 | 可选会话 id；新会话不伪造 id                                                               |
| `apiProfile` / `model`     | string?                 | 可选档案 / 模型覆盖；缺省选取与模型回退由宿主 backend 处理                                 |
| `includeContext`           | boolean?                | 缺省 `false`；只有显式 `true` 才附带上下文，并要求 `privacy.scopes` 声明 `messages`        |
| `optimizationInstructions` | string?                 | 可选优化 meta prompt / 策略；原值最多 8000 Unicode 码点，trim 空值省略，不覆盖固定安全底线 |
| `contextRounds`            | number?                 | 非负整数，上下文轮数；backend 决定缺省与实际截取规则                                       |
| `onChunk`                  | (delta: string) => void | 可选增量回调，不是累计全文                                                                 |
| `signal`                   | AbortSignal?            | 可选取消信号；取消以 `AbortError` 拒绝 Promise                                             |

宿主为每次请求创建独立 UUID，走专用优化与取消通道，不取消普通聊天会话，也不把优化请求或结果保存为会话消息。成功、失败与取消时清理取消监听器；停止后不再向插件交付增量。上下文声明缺失在调用 backend 前拒绝，不通过读取其他元数据或普通会话接口绕过 `privacy`。草稿不会自动附加 chip、附件内容或历史消息；插件应只传下面捕获结果中的 `text`，不要传 `inputText`。这是用户主动把草稿交给模型处理，不需要新增敏感 scope，插件仍须清楚提示可能产生 API 费用。

旧运行版本不保证具备新能力，`minAppVersion` 也不是运行时门禁。面板先检查 `typeof api.ai?.optimizePrompt === "function"`，再通过 `api.write.domains()` 检查三个草稿动作是否存在；缺失时显示升级提示或只读预览，不得改用 DOM 猜写或普通会话调用。

三个公开 `chatInput` 写动作使用原有标准响应 `{ ok, action, data, error?, denied? }`，无新 privacy scope；先检查 `ok`，再取 `data`：

| 动作                     | 参数                                   | 成功时 `data`                                                                             |
| ------------------------ | -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `chatInput.captureDraft` | `{}`                                   | `{ draftToken: string, inputText: string, text: string, conversationId: string \| null }` |
| `chatInput.applyDraft`   | `{ draftToken: string, text: string }` | `{ restoreToken: string }`                                                                |
| `chatInput.restoreDraft` | `{ restoreToken: string }`             | `{ restored: true }`                                                                      |

- `captureDraft` 要求真实输入区已挂载且可编辑。`inputText` 是宿主采集的完整原稿（保留 `@@file/image/...@@` 等编码 chip）；`text` 只含纯文本，不展开 chip，也不读取文件、图片或引用附件内容。
- `applyDraft` 只替换纯文本，将捕获的 chip 按原顺序原样保留在新文本后；拒绝含编码 chip 的替换文本。成功后用户仍需自行发送。`restoreDraft` 还原捕获时的完整原始输入，二者都通过 `useChatInputController.restoreContent` 同步界面、即时草稿镜像与草稿池，不发送消息。
- 令牌是宿主私有内存表中的随机 UUID，最多 128 个、5 分钟失效、单次使用，绑定插件 id、输入区唯一实例、项目、真实 / pending 会话、draft revision、实际原稿。令牌不应保存到插件 storage，也不能跨插件使用。
- 用户编辑、程序写回、会话 / 项目切换、进入流式生成 / 停止 / 压缩、输入区卸载都会使旧结果不可写回；输入文本先 A→B→A 也因同步修订递增而拒绝，不能只按文本相等认定仍有效。还原同样校验优化后的实际输入与修订，用户改过就不再覆盖。
- 失败返回 `ok: false` 与 `error`，原文不变；令牌失效后重新捕获并让用户确认，不静默覆盖。读取 `runtime.chatInput.inputText` 或入口 prop 只能用于预览，旧快照不能替代安全捕获。

示例流程（在按钮点击处理器中执行；预览后应用 / 还原分别由用户按钮触发）：

```javascript
const captured = await api.write.run("chatInput.captureDraft", {});
if (!captured.ok) throw new Error(captured.error);
const controller = new AbortController();
const result = await api.ai.optimizePrompt({
  draft: captured.data.text,
  conversationId: captured.data.conversationId ?? undefined,
  includeContext: false,
  signal: controller.signal,
  onChunk: (delta) => appendPreview(delta),
});
// 用户确认应用时：
const applied = await api.write.run("chatInput.applyDraft", {
  draftToken: captured.data.draftToken,
  text: result.content,
});
// 用户点击还原时，只有 applied.ok 才能使用其 restoreToken：
if (applied.ok) {
  await api.write.run("chatInput.restoreDraft", {
    restoreToken: applied.data.restoreToken,
  });
}
// 取消按钮 / 面板卸载时调用 controller.abort()。
```

### 6.2 消息结束插槽（Message footer v1，ESM-only）

插件可在 `plugin.json` **顶层**贡献正式消息结束插槽，与现有 `panels`、输入 Action 并存：

```json
{
  "renderMode": "esm",
  "entry": "index.js",
  "contributions": {
    "messageFooters": [
      { "id": "files", "entry": "footer.js", "exportName": "mountFooter" }
    ]
  }
}
```

- 仅 `renderMode: "esm"` 加载 footer v1；`iframe` 的贡献被忽略，不会改为 ESM 或升级权限。没有贡献的旧插件维持原行为。
- 每个插件只检查前 16 项；`id` 必须匹配 `[A-Za-z_][A-Za-z0-9_-]*`，同插件内去重；`exportName` 必须是完整 JavaScript 导出标识，不是 `obj.mount` 等表达式。宿主按该名字查找函数，不推断 React 组件。
- `entry` 使用插件目录内安全相对路径（例如 `ui/footer.js`），禁止绝对路径、盘符、反斜杠、空路径段、`.` / `..`、URL、编码路径和查询/片段；仅省略时回退到插件 `entry`，显式非法值不会回退。
- 面板可用 `api.ui.messageFooterVersion === 1` 探测宿主支持；旧宿主未提供该字段时，可在自己的面板给出兼容提示，而不要查询聊天 DOM 注入替代界面。

挂载契约是**同步 DOM 挂载函数**：

```javascript
export function mountFooter(container, api, context, signal) {
  let subscription;
  const render = (response) => {
    if (signal.aborted) return;
    const current = response.domains.runtime?.conversation;
    if (current?.conversationId !== context.conversationId) return;
    container.textContent = api.t("footer.completed", {
      defaultValue: "回复已结束",
    });
  };
  void (async () => {
    // subscribe 返回 Promise<MetadataSubscription>，必须 await 后才可 unsubscribe。
    const sub = await api.metadata.subscribe("runtime", render);
    if (signal.aborted) {
      sub.unsubscribe();
      return;
    }
    subscription = sub;
  })().catch(() => {
    if (!signal.aborted) api.log("Footer subscription unavailable");
  });
  return () => {
    subscription?.unsubscribe();
    container.replaceChildren();
  };
}
```

`mountFooter(container, api, context, signal)` 可返回 `void`、清理函数或 `{ unmount() }`；不能返回 Promise。`container` 是此贡献专属的 DOM 容器，插件只在它里面挂载。`context` 冻结为 `{ slot: "message-footer", conversationId, messageId, directoryId }`（未知目录为 `undefined`），不携带正文、思维或文件记录；这些数据必须通过有隐私检查的元数据接口按需读取，宿主不计算文件统计或 worktree 数据。

Footer 的 `api` 是**受生命周期约束的读取子集，加上文件阅读器与只读 diff 导航能力**：插件身份字段、`t`、`log`、`assets.resolve`、`ui`（含 `React`、`icon`、`messageFooterVersion`）以及 `metadata.get / subscribe / domains`；另提供冻结的 `write: { domains, run }`，不提供完整写域语法糖、`ai`、`net`、`storage`。`write.domains()` 只列出 `panels.openFile` 和 `panels.openFileDiff`（参数与返回见 8.5），插件应探测目标动作的 `id` 与 `granted` 后，在用户点击时通过 `write.run` 请求文件阅读或真实 patch 预览。其他动作在 footer 层返回 `{ ok: false, action, denied: { reason: "unsupported-runtime" }, error }`，不会委托到宿主写动作。调用前检查 `signal` 与当前会话/挂载身份；失效的 `run` 返回 `{ ok: false, action, error: "Footer context expired" }`，迟到的结果不交付（已发出的导航请求不会被回滚）。元数据默认补入此挂载的 `conversationId` 和已知 `directoryId`，调用方仍可显式指定参数，不补造跟踪根目录；原 `privacy` 声明与字段剥离规则不变。失效后读调用及 `write.domains()` 拒绝为 `AbortError`、日志不再输出，迟到的 `get` / 资源结果不交付，订阅回调不再触发。

仅当前焦点会话的**最后一条非 tool 消息是本条已结束 assistant 回复**，且未流式、暂停或中止时挂载；新的 user 消息进入就隐藏旧 footer。禁用、卸载、刷新后记录替换、切会话/回复、新 run、语言切换和组件卸载都会中止 `signal` 并清理容器、样式与订阅。宿主拥有 `subscribe` 返回的 Promise 及订阅：即使插件未返回 cleanup，或 Promise 在卸载后才完成，也会取消订阅；cleanup 抛错不会阻止自身资源回收。一个插件失败不影响其他 footer 或聊天。

> 受限 API 和生命周期回收**不是沙箱安全承诺**：ESM 模块初始执行仍在主渲染进程，已有 `window.SnowAppPlugin` 全局加载机制不具隔离性，仅安装可信插件。Footer 插件应使用显式传入的 `api` / `container`，不要捕获全局 API 或操作容器外 DOM。启用/停用使用现有插件管理流程，不会自动执行写动作或 AI。

### 7. 可读取的元数据域与隐私声明

未在 `privacy` 中声明的**整域敏感域**在 `denied` 中返回 `{ reason: "privacy-declaration-missing", scope }`，`domains` 里不会出现该域。可用域共 34 个：**每个域的可用参数、返回字段与典型用途见 [插件元数据域参考](../3-参考手册/6-插件元数据域参考.md)**；下表先给出声明要求总览：

| `app`、`theme`、`settings`、`apiProfiles`、`mcp`、`subAgents`、`hooks`、`skills`、`lsp`、`permissions`、`codebase`、`projects`、`scheduledTasks`、`runtime`、`panels`、`ide`、`imageLibrary`、`pets` | —                           | 这 18 个域无需声明即可读取；`theme`、`settings`、`apiProfiles`、`mcp`、`subAgents`、`scheduledTasks` 仍会剥离个别敏感字段 |

| `systemPrompts`                                                                                                                                                                                      | `systemPrompts`             | 系统提示词                                                                                                                |
| `customHeaders`                                                                                                                                                                                      | `customHeaders`             | 自定义请求头方案                                                                                                          |
| `personalization`                                                                                                                                                                                    | `personalization`           | 全局 ROLE 规则                                                                                                            |
| `conversations`、`messages`                                                                                                                                                                          | `conversations`、`messages` | 会话与消息                                                                                                                |

| `logs`、`usage`、`git`、`ssh`、`userscripts`、`remoteControl`、`plugins`                                                                                                                             | 同名域                      | 日志、用量、Git、SSH、油猴脚本、远控、插件清单                                                                            |

### 8. 可写能力（`api.write`）

`api.metadata` 负责读，`api.write` 负责写，两者共用同一套隐私声明规则：写动作的 `scope` 非空时，必须在 `plugin.json` 的 `privacy` 中声明，否则调用会被拒绝。

#### 8.1 调用形态与返回结构

```javascript
// 按动作 id 调用（ESM 与 iframe 都可用）
const created = await api.write.run("memos.create", {
  directoryId: "local:/path/to/project",
  content: "买牛奶",
});

// ESM 面板还有按域展开的语法糖，等价于上一行
const same = await api.write.memos.create({
  directoryId: "local:/path/to/project",
  content: "买牛奶",
});

// 列出全部写动作与声明状态
const domains = api.write.domains();
// [{ id, granted, actions: [{ id, scope, granted, summary }] }]
```

- ESM 运行时：`api.write.<domain>.<action>(params)` 与 `api.write.run("<domain>.<action>", params)` 等价，`api.write.domains()` 返回按域分组的动作清单（`scope` 为 `null` 表示公开动作）。
- iframe 运行时：桥只暴露 `api.write.run` 与 `api.write.domains`，没有按域展开的语法糖。
- 写入**不会抛异常**，始终返回同一结构：

| 字段     | 类型    | 说明                                                                        |
| -------- | ------- | --------------------------------------------------------------------------- |
| `ok`     | boolean | 是否执行成功                                                                |
| `action` | string  | 本次调用的动作 id（`domain.action`）                                        |
| `data`   | unknown | 成功时的返回值；动作无返回值时为 `null`                                     |
| `denied` | object  | 被拒绝时的 `{ reason, scope? }`，见 8.2                                     |
| `error`  | string  | 失败说明；参数非法时指出哪个参数不合法，这类失败只有 `ok: false` 与 `error` |

#### 8.2 失败与 `denied` 判定

| `denied.reason`             | 含义与处理                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------ |
| `write-declaration-missing` | 动作需要 `scope`（由 `denied.scope` 给出）但 `privacy` 未声明；声明后重装或 `rescan` |
| `unknown-action`            | 动作 id 不存在（拼写错误或跨版本差异）；先用 `api.write.domains()` 核对现有动作      |
| `unsupported-runtime`       | 当前运行时不允许该动作（预留值，当前两种运行时都不返回）                             |

参数缺失或类型不符、后端调用失败时只有 `ok: false` 与 `error`，没有 `denied`；因此 `api.write` 可以像读接口一样直接 `await`，不需要 try/catch。

#### 8.5 写动作速查表：系统与界面（14 个）

`panels.openFileDiff` 是公开、纯内存只读 UI 导航（`scope: null`）。在用户点击时调用 `api.write.run("panels.openFileDiff", { filePath, patch, changeType })`，其中 `filePath` 和真实 unified diff `patch` 必须为非空字符串且不能含 NUL；`changeType` 严格为 `added`、`modified` 或 `deleted`。路径仅用于标签标识、提示和文件名推断（兼容 `/` 与 `\` 分隔），不要求文件存在，不读盘、不执行命令、不开放文件编辑、不伪造旧新全文。宿主将原始 patch 发给既有 `open-file-diff-preview`，复用 `file-diff-preview` 标签。返回 `{ ok: true, action: "panels.openFileDiff", data: { requested: true, filePath, changeType } }`，不返回 patch 或文件内容；`requested` 仅确认导航事件发出，不保证面板已挂载或 patch 已成功渲染。参数错误返回标准失败响应。ESM 面板也可用 `api.write.panels.openFileDiff(params)`，footer 仅有 `write.domains / run`；调用前探测动作是否存在与 `granted`。此动作不授予 `filesystem` / `ssh` 权限。

`panels.openFile` 是公开 UI 导航动作（`scope: null`），通过已有 `open-file` 事件请求内置右侧阅读器打开文件，不读取或向插件返回内容，也不授予 `filesystem` / `ssh` 敏感元数据权限。建议仅在用户点击文件时调用。

```js
const result = await api.write.run("panels.openFile", {
  filePath: "D:/project/src/main.ts",
  focusLine: 12,
});
// { ok: true, action: "panels.openFile",
//   data: { requested: true, filePath: "D:/project/src/main.ts", isSsh: false } }
```

- `filePath` 必填非空字符串。本地支持 Windows 盘符绝对路径、UNC 和 POSIX 绝对路径；不接受相对路径、`file://`、`ssh://` 文件 URL，不解析 `:line` / `#Lline` 后缀。
- `focusLine` 可选，为从 1 开始的正安全整数。文件名和标签标题由阅读器从路径推断。
- SSH 调用必须使用远程 POSIX 绝对路径（如 `/home/user/project/main.ts`），并传 `sshWorkspacePath: "ssh://user@host/home/user/project"`；可选 `sshWorkspaceId` 用于既有远程草稿绑定。连接、凭据解析、工作区写入边界与错误呈现均沿用宿主阅读器。不接受插件传入的 SSH 会话 ID、凭据或文件内容。
- `requested: true` 只表示事件已发出，**不保证文件存在、面板已挂载、SSH 已连接或文件已加载**；异步加载结果由内置阅读器负责，不会返回给插件。参数错误仍返回通用 `{ ok: false, action, error }`。
- ESM 可用 `api.write.panels.openFile(params)`；iframe 使用 `api.write.run`。旧宿主可先用 `api.write.domains()` 检查动作是否存在。

#### 8.8 用户侧可见性

- 插件页面每行的「可写能力 X/Y」徽章：X 是该插件已声明可写动作数，Y 是动作总数（206）；只要声明的 scope 覆盖到动作就计入 X。
- 「元数据清单」标签页的「可写能力」子标签：逐个动作列出 `domain.action`、所需 `scope`（公开动作显示「公开」）与声明状态（「可写」/「未声明」），并支持与元数据相同的关键词搜索。
- 两个入口由同一份 `api.write.domains()` 数据生成，面板里也可以用它自查当前声明状态。

### 9. 本地化与样式

- 语言包是**扁平 JSON**（`{"key": "文案"}`），文件名与键名自定；`api.t` 取不到时按 `defaultValue`、键名依次回退。
- `locales` 按当前语言精确匹配 → 同语言小写匹配 → 主语言（`zh` / `en`）匹配 → `default` → 首个条目的顺序挑选文件。
- `styles` 里的 CSS 以 `<style data-snow-plugin="<id>">` 注入文档头，面板卸载时移除；选择器建议加插件前缀避免影响应用界面。
- 面板图标可用 `panels[].icon` 单独覆盖插件图标（同样是 `lucide:Name` 或相对路径）。

### 10. 让 AI 自动安装插件（`config` 工具的 `plugins` 域）

不必打开插件页面，AI 可以直接写文件并安装：

```text
# 1) 先把插件目录写到磁盘（filesystem 工具）
filesystem-create ./my-plugin/plugin.json
filesystem-create ./my-plugin/index.js

# 2) 安装（key 用 "new"，真实 id 以 plugin.json 为准）
config-set scope=plugins key="new" value={sourceDir: "/abs/path/my-plugin"}
#   也接受 value={sourcePath: "/abs/path/my-plugin/plugin.json"}

# 3) 查看 / 启停 / 重载清单
config-list scope=plugins
config-get  scope=plugins key=com.example.hello
config-set  scope=plugins key=com.example.hello value={enabled: false}
config-set  scope=plugins key=com.example.hello value={rescan: true}

# 4) 卸载（需用户确认；deleteFiles 缺省 true，连目录一起删）
config-delete scope=plugins key=com.example.hello confirmed=true
config-delete scope=plugins key=com.example.hello value={deleteFiles: false} confirmed=true
```

要点：

- `sourceDir` 与 `sourcePath` 都接受绝对路径、`~/` 路径与相对当前工作目录的路径；传文件路径时取其所在目录。
- 安装使用与 UI 完全相同的存储层，因此复制目录、跳过清单、注册数据库、默认启用等行为一致；**面板宿主不会自动刷新列表**，打开插件页面或面板时会重新读取。
- 卸载是破坏性操作：`config-delete` 要求先经用户确认再携带 `confirmed: true`。

### 11. 插件市场（安装、更新与发布）

「插件市场」标签页读取索引仓库 [snow-plugin-store](https://github.com/MayDay-wpf/snow-plugin-store) 的 `app/registry.json`，一键安装或更新面板插件与用户脚本：插件本体由各作者自己的 GitHub 仓库以 Release 资产分发，客户端按索引锁定的 SHA-256 校验通过后才安装。索引在打开该标签页时拉取（60 秒内复用内存缓存，**刷新** 强制重取）：主源 GitHub raw 失败时自动改走 jsDelivr 镜像，两者都失败时回退最近一次成功的磁盘缓存（`~/.snowapp/plugin-market/registry.json`）。

#### 11.1 在客户端安装与更新

- 每个条目显示名称、版本、作者、标签与类型（脚本条目带「脚本」标注），支持按名称、描述、作者与标签搜索；`icon` 为 `lucide:Name` 时解析为对应图标，否则用占位图标。
- 未安装时按钮为 **安装**；已安装且索引版本不更高时显示「已安装」；索引版本更高时显示 **更新** 与 `已安装 v<旧版本> → v<新版本>` 提示——更新为原地覆盖：面板插件保留启用状态，脚本重新匹配并保持启用状态。
- 条目声明了 `privacy` 敏感域时逐枚显示琥珀色徽章，点击打开统一的「隐私域声明」弹窗；条目的 `minAppVersion` 高于当前应用版本时禁用安装并提示「需要应用 v<版本> 或更新版本」。
- 点击安装/更新先显示确认弹窗：版本、作者、描述、来源仓库链接、SHA-256 前 16 位与隐私徽章；确认后由 Rust 侧执行下载 → SHA-256 校验 → 安装。
  - 面板插件：下载 zip（`plugin.json` 位于 zip 根目录，或唯一顶层子目录下），解压后校验 `plugin.json` 的 `id` 必须等于条目 `id`，再复用与「从目录安装」相同的存储层；`source_path` 记录条目仓库地址，供更新展示与来源核对。
  - 脚本条目（`kind: "script"`）：直接下载 `.user.js` 文件，以条目 `id` 作为脚本标识写入 `userscripts` 表并立即重新匹配生效；同一 id 再次安装为原地更新，不影响启用状态。

大小限制与本地安装一致：zip 上限 128 MB，解压后总量上限 512 MB，脚本文件上限 10 MB。

#### 11.2 发布插件到市场（作者流程）

上架与更新都通过在索引仓库 [snow-plugin-store](https://github.com/MayDay-wpf/snow-plugin-store) 提 PR 完成，合并后客户端刷新即可看到新版本：

```mermaid
flowchart TD
    A[打包 zip 或准备脚本文件] --> B[创建 GitHub Release 并上传资产]
    B --> C[计算 SHA-256]
    C --> D[提交 app/plugins 索引条目]
    D --> E[CI 校验全部条目]
    E --> F[合并后自动重建 registry.json]
    F --> G[客户端刷新并安装或更新]
```

1. **准备插件**：按本文规范编写插件；脚本条目按 [22-油猴脚本](22-油猴脚本.md) 的客户端脚本规范编写，并先在本地完成一次安装自测。
2. **发布 Release**：把插件目录打包为 zip——`plugin.json` 必须在 zip 根目录，不要套一层文件夹——在插件自己的 GitHub 仓库创建 Release（tag 建议语义化版本，如 `v1.2.0`）并把 zip 作为 Release 资产上传；脚本条目直接上传单个 `.user.js` 文件（不要打包）。
3. **计算 SHA-256**：Linux / macOS 用 `sha256sum my-plugin-1.2.0.zip`，Windows 用 `Get-FileHash .\my-plugin-1.2.0.zip -Algorithm SHA256`；脚本文件同理。哈希必须对应 Release 资产的原始字节。
4. **提交索引条目**：新增或更新 `app/plugins/<id>.json`（一插件一文件，文件名必须等于 `<id>.json`），提交 PR；本地可先运行 `node app/scripts/validate-registry.mjs` 校验。
5. **合并生效**：CI 校验通过并由维护者合并后自动重建 `app/registry.json`（不要手动编辑它）；客户端「插件市场」**刷新** 后即可一键安装或更新。

条目字段（权威 JSON Schema 为仓库内的 `app/entry.schema.json`）：

| 字段                   | 必填 | 说明                                                                                                                                           |
| ---------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | 是   | 唯一 ID；面板插件必须与 `plugin.json` 的 `id` 完全一致。字母、数字、`.`、`-`、`_`，最长 96，不能以 `.` 开头                                    |
| `kind`                 | 否   | `plugin`（默认，面板插件）或 `script`（用户脚本，Release 资产是 `.user.js` 文件本身）                                                          |
| `name` / `description` | 是   | 展示名与简介，字符串或本地化对象（如 `{"default": "...", "zh-CN": "..."}`）                                                                    |
| `repo`                 | 是   | 插件仓库地址，形如 `https://github.com/owner/repo`                                                                                             |
| `version`              | 是   | 版本号，与 Release 内容一致                                                                                                                    |
| `tag` / `asset`        | 条件 | Release tag 与资产文件名；未提供 `downloadUrl` 时两者必填，下载地址按 `https://github.com/<owner>/<repo>/releases/download/<tag>/<asset>` 推导 |
| `downloadUrl`          | 否   | 显式指定资产直链（https）；提供后不再按 `tag`/`asset` 推导                                                                                     |
| `sha256`               | 是   | 资产 SHA-256（64 位十六进制）                                                                                                                  |
| `author` / `homepage`  | 否   | 作者署名与主页 / 文档地址                                                                                                                      |
| `minAppVersion`        | 否   | 要求的最低应用版本；低于它的客户端禁用安装并提示                                                                                               |
| `privacy`              | 否   | 敏感数据域列表，与插件 `plugin.json`（脚本为 `@snow-privacy`）的声明保持一致，用于市场徽章与安装确认                                           |
| `tags`                 | 否   | 检索关键词                                                                                                                                     |
| `icon`                 | 否   | 市场列表图标，如 `lucide:Puzzle`；缺省显示占位图标                                                                                             |

> 合并条目只代表索引格式与哈希校验通过，不代表对插件行为的安全背书——插件代码仍由作者仓库分发，安装前请核对来源与隐私声明。

## 验证

- `config-list scope=plugins` 返回 `items` 中包含新插件、`enabled` 为 `true`，`pluginsDirectory` 指向 `~/.snowapp/plugins`。
- 安装目录内存在 `plugin.json` 与入口文件，目录名为 `plugin.json` 里的 `id`。
- 插件页面列表出现该插件；顶栏加号菜单的「插件」分组出现其面板，点击后右侧面板打开且无加载错误。
- 面板需要元数据的域已授权时 `api.metadata.get` 的 `denied` 为空。
- 面板需要写入的动作已授权时 `api.write.run` 返回 `ok: true`；未声明时返回 `denied.reason = "write-declaration-missing"` 与所需 `scope`，`api.write.domains()` 能列出全部动作及声明状态。
- 「插件列表 → 脚本插件」的计数与列表只包含 `target` 为 `client` / `all` 的脚本，同样是 `client` 的脚本不会出现在「设置 → 浏览器设置 → 油猴脚本」列表里。
- 「插件市场」能加载条目列表并显示隐私徽章；安装面板插件后「插件列表 → 面板插件」出现且默认启用，安装 `kind: "script"` 条目后「脚本插件」出现该脚本。
- 索引版本高于本地版本时条目显示 **更新** 与版本提示，安装后变为「已安装」；`minAppVersion` 高于当前版本的条目安装按钮被禁用。
- 「面板插件」与「脚本插件」列表中的已安装项在索引版本更高时同样显示 **更新** 按钮，点击后原地更新并保持启用状态。

## 常见问题与恢复

| 现象                                                                                   | 原因与处理                                                                                                      |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `Missing plugin.json in '...'`                                                         | 选中的目录不含清单文件；请选择包含 `plugin.json` 的那一层                                                       |
| `Plugin id is required and may only contain letters, digits, dot, dash and underscore` | `id` 缺失或含非法字符（如空格、中文、以 `.` 开头）                                                              |
| `Plugin entry file 'index.js' is missing`                                              | `entry` 指向的文件不存在（复制前先确认文件已写入）                                                              |
| `Plugin directory is too large to install (limit 128 MB)`                              | 目录过大；`node_modules` 与 `.git` 虽被跳过，仍需自行清理其它大文件                                             |
| `Plugin manifest id 'x' does not match 'y'`                                            | 重新读取清单时 `plugin.json` 的 `id` 被改过；改回原 id 或按新 id 重新安装（旧记录需卸载）                       |
| 面板提示入口无效                                                                       | 入口未导出默认 React 组件，也未导出 `mount(container, api)` / `render(...)`                                     |
| `denied` 中出现 `privacy-declaration-missing`                                          | 在 `plugin.json` 的 `privacy` 中声明对应敏感域后重新读取清单（可重装或 `rescan`）                               |
| 手工改了安装目录后界面没变                                                             | 点 **重新读取清单** 或 `config-set ... value={rescan: true}`；列表本身可用 **刷新** 重载                        |
| 卸载后想保留源码                                                                       | 用 `value={deleteFiles: false}` 卸载（或先备份 `~/.snowapp/plugins/<id>/`），目录不会被删除                     |
| 客户端脚本在浏览器设置里找不到                                                         | 属预期：`@snow-target client` 的脚本只在「插件 → 插件列表 → 脚本插件」管理，浏览器列表只显示 `browser` 与 `all` |
| `api.write` 返回 `denied.reason = "write-declaration-missing"`                         | 该写动作需要 `scope`（见 `denied.scope`）；在 `plugin.json` 的 `privacy` 中声明后重装或 `rescan`                |
| `api.write` 返回 `denied.reason = "unknown-action"`                                    | 动作 id 拼写错误或该版本没有这个动作；用 `api.write.domains()` 列出可用动作                                     |
| `api.write` 返回 `ok: false` 但没有 `denied`                                           | 参数校验或后端调用失败；按 `error` 里指出的参数名修正入参                                                       |
| 插件市场加载失败（`Failed to fetch the plugin market index`）                          | 主源与 jsDelivr 镜像都不可达且没有可用缓存；检查网络/代理后点 **刷新** 重试                                     |
| `Plugin archive SHA256 mismatch (...)`                                                 | Release 资产与索引条目的 `sha256` 不一致：资产被重打包或条目未更新；重新计算哈希并更新条目                      |
| `Plugin archive id 'x' does not match the market entry 'y'`                            | zip 内 `plugin.json` 的 `id` 与索引条目 `id` 不一致；修正后重新发 Release 并更新条目                            |
| 市场条目的安装按钮被禁用并提示「需要应用 vX.Y.Z 或更新版本」                           | 当前应用版本低于条目的 `minAppVersion`；升级应用后再安装                                                        |
| 索引已更新但市场列表仍是旧内容                                                         | 60 秒内存缓存内复用旧结果；点 **刷新** 强制重新拉取                                                             |
