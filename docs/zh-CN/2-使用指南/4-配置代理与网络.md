# 4-配置代理与网络

Snow App 的代理设置作用于应用会话网络请求、web 搜索与内置浏览器。本指南介绍代理、搜索引擎、浏览器以及全局站点拦截规则。

## 1. 认识配置入口

| 入口 | 说明 |
| --- | --- |
| 设置 → 代理与浏览器（设置页 id：`proxy-browser-settings`） | 图形界面：代理、搜索引擎、内置浏览器和站点拦截规则 |
| `~/.snow/proxy-config.json` | `config` 的 `proxy` scope 使用的文件型代理、搜索引擎和浏览器配置 |
| 应用数据库系统设置 `proxy_browser_settings` | UI 使用的完整代理浏览器设置，其中包含 `blockedPatterns` |

代理、搜索引擎和浏览器字段由文件型 `proxy` scope 管理；设置面板同时把完整设置保存到应用数据库。`blockedPatterns` 不属于 `proxy-config.json`，实际以应用数据库的 `proxy_browser_settings` 为准。

## 2. 配置代理

| 字段 | 说明 |
| --- | --- |
| `enabled` | 启用开关，是否使用代理 |
| `host` | 代理主机，如 `127.0.0.1` |
| `port` | 代理端口，如 `7890` |

## 3. 配置搜索引擎

| 字段 | 说明 |
| --- | --- |
| `searchEngine` | 搜索引擎，如 `bing`、`duckduckgo` |

该设置影响 `websearch` 工具的搜索结果来源。

## 4. 配置内置浏览器

| 字段 | 说明 |
| --- | --- |
| `browserPath` | 浏览器可执行文件路径；留空时自动检测 Chrome / Edge / Chromium，也可点击 Browse 手动选择 |
| `browserDebugPort` | 浏览器调试端口，如 `9222` |

调试端口用于内置浏览器面板的连接；端口被占用时面板可能无法打开。

## 5. 站点拦截规则

`blockedPatterns` 是应用全局的站点拦截规则数组，不属于项目设置，也不随当前 `projectId` 改变。每行配置一条 JavaScript 正则表达式，设置面板和专用 app-control 更新工具会使用 JavaScript `RegExp` 校验规则。

规则的作用范围：

- `websearch` 搜索结果命中规则后会被过滤；
- `websearch-fetch` 抓取目标命中规则后会拒绝抓取；
- 非法 JavaScript 正则无法正常保存或更新；Rust 抓取侧使用的 `regex::Regex` 与 JavaScript `RegExp` 语法不完全一致，Rust 无法编译的规则会被跳过或不生效。

推荐使用带边界的域名规则。例如在 JSON 工具参数中写成 `(^|\\.)example\\.com$`：`(^|\\.)` 表示域名开头或前面的点，允许匹配 `example.com` 及其子域名；`$` 表示匹配必须在域名末尾结束，避免误匹配更长的域名。不要把用户输入直接当作正则而不检查转义。

AI 可使用专用工具维护规则：

| 工具 | 作用 |
| --- | --- |
| `app-control-getBlockedPatterns` | 读取当前全局规则数组和规则数量 |
| `app-control-updateBlockedPatterns` | 按操作添加、删除或完整替换规则 |

`app-control-updateBlockedPatterns` 参数：

```json
{
  "operation": "add | remove | replace",
  "patterns": ["(^|\\\\.)example\\\\.com$"]
}
```

操作语义：

- `add`：去除首尾空白，精确去重，并保持已有规则顺序；
- `remove`：按完整字符串精确删除；
- `replace`：用传入数组完整替换当前规则；
- `patterns` 必须是非空字符串数组元素，每条规则都要通过 JavaScript 正则校验。

## 6. 生效范围

- **应用会话代理**：网络请求、更新检查；
- **web 搜索**：`websearch` 工具，受站点拦截规则过滤；
- **网页抓取**：`websearch-fetch` 工具，受站点拦截规则拒绝；
- **内置浏览器面板**：嵌入式浏览器实例；
- **站点拦截规则**：全局应用设置，不是项目级配置。

## 7. AI / 命令行配置（config 工具）

`config` 工具可以读写文件型 `proxy` 域，但该域不支持 `blockedPatterns`：

| 工具 | 示例 |
| --- | --- |
| `config-get scope=proxy` | 查看 `proxy-config.json` 支持的代理、搜索引擎和浏览器字段 |
| `config-set scope=proxy value={enabled: true, host: "127.0.0.1", port: 7890}` | 启用代理 |
| `config-set scope=proxy key=searchEngine value="duckduckgo"` | 切换搜索引擎 |
| `config-set scope=proxy key=browserPath value="C:\\\\Program Files\\\\Google\\\\Chrome\\\\Application\\\\chrome.exe"` | 设置浏览器路径（Windows 反斜杠需转义） |

不要使用 `config-get scope=proxy key=blockedPatterns` 或 `config-set scope=proxy key=blockedPatterns` 维护运行时规则；它们不在当前 `PROXY_SCOPE_KEYS` 白名单中。站点拦截规则应通过设置面板，或通过上述专用 app-control 工具维护。文件型配置写入后可能需重启应用或重新保存 UI 设置生效；专用 app-control 更新会直接写入应用数据库并重新应用代理设置。

## 8. 常见问题

| 症状 | 原因与处理 |
| --- | --- |
| 搜索结果仍包含被拦截站点 | 检查规则是否为有效 JavaScript 正则，并确认规则能匹配结果中的域名 |
| 页面抓取被拒绝 | 目标域名命中了全局 `blockedPatterns`；读取规则确认是否需要移除 |
| 浏览器面板打不开 | 检查 `browserPath` 是否正确，或调试端口被占用 |
| 修改后没生效 | 确认已保存；规则更新后会重新应用代理设置 |
