# ADR：子代理结果消息标识与既有会话 UI 复用

- 日期：2026-10-23
- 状态：修复决策已确定；编译与运行验收单独记录。
- 范围：子代理事件接收的消息 ID 边界，以及侧边栏既有子代理列表。

## 背景

`listChatMessages` 返回 `chat_messages.id`，会话内存消息与工具边界也使用此 ID。异步 `receive` 创建内部 assistant/tool 消息时，事件回执保存的是 `chat_messages.message_id`；直接把它作为 `messageIds` 返回会使前端误报 `committed parent input is missing`。主动 getResult/wait 的确认又用 `message_id` 查询前端传入的行 ID，导致同类去重失败。

异步仅改变调度与结果投递时机。现有主会话展开、子代理列表、点击切换和状态图标已提供执行入口；再添加“后台／待处理”运行列表会重复展示，且把未投递事件误当成需要用户操作。

## 决策

1. 对外 `receive.messageIds` 和输入 `toolMessageId` 统一遵循现有消息 API 的 `chat_messages.id` 契约，不改变 JSON 字段、表结构或会话消息 API。
2. `verify_tool_message` 只按行 ID、父会话、tool 角色和 sent 状态校验。不得放宽事件身份、项目／父任务作用域或结构化工具结果校验。
3. 保留既有事件回执的内部标识存储。返回 `messageIds` 前，在同一事务内把回执标识解析为父会话的行 ID；优先精确行 ID，兼容已有的 `message_id` 标识。不存在则返回持久化错误，事务不提交。兼容映射只针对可信数据库回执，不放宽调用方的 `toolMessageId`。
4. 接收幂等重放返回相同的行 ID，不重复插入消息；多事件共享工具消息时，返回的行 ID 去重。禁止通过吞掉前端缺失错误、伪造消息或自动重跑工具来处理。
5. 侧边栏移除独立的“后台／待处理”计数与运行卡片列表。保留既有会话展开、子代理切换、需输入提醒、运行状态图标、删除门禁及失败重试。运行详情和取消等动作继续由既有工具卡片与子代理会话提供。
6. queued、running、waiting_input、finalizing、cancelling 等真实状态复用子代理列表的既有图标与语义样式；未投递结果不是用户授权／输入请求，不单独触发需操作状态。
7. 不增加依赖、数据库迁移、业务私有样式、内联样式、测试文件或伪造业务数据。不修改既有时间存储契约，不改正在运行实例或历史业务数据。

## 执行方式设置

子代理设置页提供全局执行方式选择，复用 `system_settings` 的通用读写 IPC，键为 `sub_agent_execution_mode`，值仅允许 `sync` 或 `async`。未保存时默认为同步；用户保存后该选择是硬约束，不是模型参数的默认建议。activate 与终态 continue 在受理前读取设置，模型传入的 `executionMode` 仅校验格式，不覆盖设置。忙碌 continue 仍只给既有运行排队消息，不改变原运行方式。设置不改已受理运行；跨窗口派发每次读取持久值，不使用陈旧窗口缓存。读取失败或非法持久值显式失败，不悄悄降级为另一种执行方式。无异步能力的入口明确拒绝异步，不偷偷执行同步。幂等请求的有效模式属于其逻辑输入，改变设置后不得复用旧 requestId 来启动另一份运行。

设置控件复用现有选择组件及公共样式，保存完成前不显示成功或切换选中值；失败保留原值。所有新增界面文案来自三语词典，不增加卡片内小字或额外后台列表。

## 执行方式与工具暴露

每次模型请求在现有全局／项目权限和工具白名单之后，按持久化执行方式裁剪父会话工具，不改写 MCP 开关或免确认授权。同步默认保留 activate、listSubAgents、continue；异步且具有项目绑定时增加 getResult、wait、cancel。切回同步后，当前项目与父会话存在历史异步运行时保留 getResult；存在非终态异步运行时还保留 wait/cancel，结束后自动收回。只读查询不消费事件、不改变运行或父任务状态、不加载完整摘要。工具设置目录仍展示完整注册项，运行请求裁剪不等于用户禁用。

工作流节点不具备异步能力：不暴露异步管理工具，异步设置下也不暴露无法执行的 activate/continue；无项目异步入口同理。子代理白名单、队友通信和受限请求沿用原有隔离规则，同步批量仍可并行。模式读取失败或非法值不按另一模式执行。工具说明按实际暴露结果生成，不无条件推荐隐藏的 wait/getResult；设置变化从下一次请求生效，已经发出的工具调用和已受理运行仍走既有校验，不强停、不重放。

## 验证边界

执行现有 TypeScript、Rust 检查、文档守卫和完整构建，并独立审查父输入映射与 UI 复用。运行验证应覆盖自动消息对、主动 getResult/wait 去重、幂等接收及既有代理切换。编译成功不等于新进程 UI／端到端验收通过；宿主需加载新 native 与 renderer 后复验。
