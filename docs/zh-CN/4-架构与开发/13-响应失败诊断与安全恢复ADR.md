# ADR：响应失败诊断与安全恢复

- 日期：2026-10-24
- 状态：实施契约冻结，验收证据另行记录。
- 范围：Chat / Responses 流内失败、失败消息读写与展示、模型恢复和工具重放边界。

## 决策

1. 不新增依赖、不改数据库 schema、不迁移真实数据库，不改变子代理执行方式、权限或 Git 状态。复用 assistant 的 raw_json 保存小型诊断对象；不保存原始 SSE、请求体、工具结果或完整异常对象。
2. 新增 native/src/api/failure.rs 作为失败诊断唯一规范化入口。ProviderFailure 为 message/code/type 三个可选字符串，message 最多 768 UTF-8 字节，code/type 各最多 128 字节；先脱敏再限长。复用 Responses 既有脱敏逻辑并收紧 URL、认证、Cookie、密钥及结构化请求回显处理，当前请求密钥必须精确替换，空密钥不参与替换。绝不将正文推断为错误。
3. IPC 保持 ResponsesApiResult.failureReason?: string|null，值仅为安全的人类可读原因。历史 ChatMessageRecord 增加同名可选字段；raw_json 使用 {providerFailure:{message,code,type}}，存储载入时规范化读取，无字段的历史 failed 消息无原因。原文和失败原因始终分开。没有可读原因时界面由纯净国际化词典提示“响应失败，未保留具体原因”。
4. Chat 流内 error 不再只输出 stderr：保留安全元数据，failed 状态独立于正文，失败调用的可执行工具必须清空，避免失败片段被执行。不扩大自动重试策略。Responses 保留既有失败分类、取消否决和安全重试策略，增加结构化诊断持久化。
5. 终态失败日志固定 message=AI response stream failed，ERROR 级别，context 为 JSON，含 conversation_id、response_id、provider、status、failure:{message,code,type} 和有限计数。不含正文、工具参数/结果、请求头/体、原始流或端点秘密。关联 ID 保留；缺 response ID 时显式为空，绝不伪造。日志失败不影响业务终态；辅助 ephemeral 请求遵守既有不持久化边界。
6. 恢复的是当前模型请求，不回滚已完成工具、不重新激活或继续子代理来重放历史操作。失败状态必须在工具调度前拦截。已完成工具结果保留为历史上下文，已有工具结果的请求若进入恢复，应明确使用已完成结果，不执行失败响应里的工具。取消优先；任何自动恢复必须有界，禁止靠提示词单独保障不重放。显式用户回滚/重新执行属于另一操作，沿用确认边界，不新增静默重放。

## 恢复边界收紧

既有重试清理会删除当前请求行，不能在含已完成工具结果时无条件复用。当前修复保守拒绝这类破坏性重试：前端在重试前检查当前请求的 tool 结果，原生侧在 IMMEDIATE 事务中检查待删范围，任何 tool 行均阻止删除。提示用户结果已保留，应基于当前会话继续，而非重放动作。不引入新的上下文去重或恢复协议；不含工具结果的模型请求仍可沿用人工重试。清理 await 后重新检查取消，再恢复运行状态。原有用户显式回滚不受此守卫替代。

## 验收边界

主代理为全套门禁唯一执行者；实施者仅运行授权范围 LSP 与自检。禁止新增测试文件、业务 Mock、伪进度、内联样式、Hex 色值或 Unicode Emoji；不访问真实数据库/收费模型、不启动服务、不操作 Git。最终运行受支持改动文件 LSP、类型检查、文档守卫、格式检查与完整构建；以无文件内存探针验证脱敏、正文/错误分离和工具恢复守卫。编译不能替代真实模型或 UI 端到端验收。
