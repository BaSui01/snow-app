# ADR：归档与删除门禁解耦

- 日期：2026-10-24
- 状态：用户确认实施；构建与真实界面验收分开记录。
- 范围：单条、批量和插件共用的会话归档；不取消永久删除的安全保护。

## 问题

归档在搬移数据前逐个执行 `prepare_delete`，分别提交持久删除门禁。准备完成不等于归档完成；后续失败或等待时，列表会显示“删除处理中”及永久删除重试入口，与用户的归档意图不符。

## 冻结契约

1. 归档不执行 `prepare_delete`，不创建持久删除门禁，不以永久删除作为恢复路径。永久删除仍沿用原有准备、取消、执行者收尾与物理清理保护。
2. renderer 归档准备只查询子代理终态并等待本地已终态执行者收尾；子代理仍活动时返回明确错误，不发起取消。确认子代理已终态后才停止父会话并释放本地会话状态。
3. Rust 在原有 ATTACH/Immediate 事务内重新检查完整后代树的 run 均为终态。持有写事务后才复制数据，不允许 renderer 的预检替代存储层校验。
4. 完整复制 run、请求、消息、事件和验收事实后，先按已复制 run ID 清理运行库 run，再清理会话。永久删除触发器无需放宽：它们仍保护有活动 run 或缺少删除准备的普通删除。归档清理与复制处于同一事务，任一步失败均回滚，不使用忽略冲突或关闭外键。
5. 已由旧归档流程留下门禁的会话可重新归档；成功删除运行库会话时由原有外键级联清除旧门禁。失败不擅自重开会话，也不补造归档成功。
6. 归档成功才清理草稿、切走被移除的活动会话并刷新列表；置顶跳过、墓碑和还原契约不变。不新增 schema、依赖、测试文件，不操作用户真实数据库或重启应用。

## 验证边界

使用源码 SQL 的隔离内存探针验证：无门禁的终态归档、旧门禁归档、复制失败回滚、活动 run 拒绝、永久删除保护仍生效及外键完整性。执行变更文件 LSP 诊断、TypeScript/Rust 检查和生产构建。真实界面中的旧 8 项需新代码加载后由用户重新归档核验，不能以源码探针代替。
