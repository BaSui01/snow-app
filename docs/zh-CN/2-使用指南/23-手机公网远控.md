# 部署手机公网远控

> 适用于 Windows 桌面版 Snow。部署过程由 Snow 内置程序完成，不调用聊天 AI，也不要求用户理解 FRP、Caddy、token、CA、PEM 或 TLS 名称。

## 目标

部署完成后，手机关闭 Wi-Fi 仍可通过 `https://snow.<你的域名>` 打开 Snow，并扫描设置页中的公网二维码完成配对。

## 需要提前准备什么

1. 一台长期运行的 Linux 公网服务器，厂商不限：Ubuntu 22.04 或 24.04、x86_64、独立公网 IPv4，推荐至少 1 核 1 GB。不要使用抢占式或竞价实例。
2. 一个自己持有的域名，注册商和后缀不限。不需要另外购买 SSL 证书、CDN、建站或企业邮箱服务。
3. 服务器的 SSH 登录方式：`root` 密码，或私钥；普通用户也可以，但必须有免密码 `sudo` 权限。

如果手机与电脑始终在同一 Wi-Fi，只需扫描局域网二维码，不需要服务器或域名。

## 只需手工完成两件事

Snow 无法通用地修改所有云厂商的控制台，因此请先完成：

1. 在域名 DNS 控制台添加两条 A 记录，记录值都填写服务器公网 IPv4：
   - 主机记录 `snow`
   - 主机记录 `frp`
2. 在服务器安全组或云防火墙中允许入站 TCP `22`、`80`、`443`、`7000`。不要开放 `18080`。

DNS 生效可能需要几分钟。Snow 设置页的“检测 DNS”会直接告诉你两条记录是否正确。

## 让 Snow 自动部署

1. 打开“设置 → 手机远控 → 自建服务器公网连接”。
2. 填写服务器公网 IPv4、根域名（例如 `example.com`）、SSH 用户名和端口。
3. 选择密码或私钥登录。密码和私钥口令只在本次部署期间保存在内存中，不写入远控配置。
4. 点击“检测 DNS”。两条记录都正确后，点击“自动部署并连接”。
5. 等待 Snow 检查系统、上传内置安装程序、安装 FRP/Caddy、生成独立凭据、导入配置并验证公网 HTTPS。

Snow 直接从安装包的固定资源目录读取部署脚本，不会让聊天 AI 搜索磁盘。服务器生成的客户端配置在内存中导入，不会在本机留下明文配置包；导入后服务器上的临时配置包也会删除。

## 验证

部署成功时，页面会显示“本机 WAN”“FRP 隧道”“HTTPS 探测”均正常，并生成公网二维码。关闭手机 Wi-Fi，使用蜂窝网络扫描二维码，测试查看会话、发送消息、停止任务和上传附件。

服务器只应公开 `22`、`80`、`443`、`7000`；`18080` 必须只监听 `127.0.0.1`。Snow 会在部署末尾检查这一点。

## 常见问题与恢复

- “DNS 尚未生效”：核对 `snow` 和 `frp` 两条 A 记录是否都指向页面中填写的公网 IPv4，等待几分钟后重试。
- 使用代理后始终显示错误的 `198.18.x.x`：这是部分 VPN/TUN 的 fake-IP。Snow 会自动通过 HTTPS 公共 DNS 复核，无需关闭代理或修改正确的 A 记录。
- “服务器系统不支持”：更换为 Ubuntu 22.04/24.04 x86_64。
- SSH 连接失败：核对公网 IP、端口、用户名以及密码或私钥；不要把密码或私钥内容发到聊天中。
- 安装完成但公网不可达：核对安全组是否允许 TCP `80`、`443`、`7000`，并确认服务器没有额外防火墙阻止它们。
- 部署中断：可直接重新点击部署。Snow 会清理临时脚本；未完整验证的配置不会保持自动连接。
- 高级用户已有服务器配置包时，可展开高级区域导入；普通用户无需使用该入口。
